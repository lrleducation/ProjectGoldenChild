PROJECT GOLDEN CHILD v2.4.1 — FINAL SUPABASE URL FIX

THE ROOT CAUSE

The website database layer and Storage layer were treating SUPABASE_URL differently.

If Vercel contained:
  https://YOUR-PROJECT.supabase.co/rest/v1

the database code stripped /rest/v1 and worked.

The Storage code did not strip it, so it constructed:
  https://YOUR-PROJECT.supabase.co/rest/v1/storage/v1/...

That is not a valid Supabase Storage endpoint and produces a 404 that looks like:
  “The event-public Storage bucket could not be found.”

v2.4.1 removes that inconsistency. Database and Storage now use one shared URL normaliser.

YOU DO NOT NEED TO RUN ANY MORE SUPABASE SQL.
