PROJECT GOLDEN CHILD v2.6.0 — UPDATE STEPS
==========================================

This update adds selected/multi-child communications and private poster attachments.

IMPORTANT: apply the database/storage migration BEFORE deploying the v2.6.0 code.

1. Open the LIVE Project Golden Child Supabase project used by Vercel.

2. Open SQL Editor and run:
   supabase/UPDATE_v2.6.0.sql

3. Check the results at the bottom of the script:
   • FINAL CHECK A must return ZERO rows.
   • FINAL CHECK B must show communication-attachments with public=false and a 10485760 byte limit.
   • FINAL CHECK C must include schema version 2.6.0.

4. Deploy this v2.6.0 ProjectGoldenChild folder/repository to Vercel.
   Keep the existing Resend, Supabase, session and appointment environment variables unchanged.

5. Hard refresh the admin page once after deployment (Ctrl+F5 on Windows).

6. Open Admin → Dashboard → System Health → Check now.
   Expected:
   • schema 2.6.0
   • all database table checks OK
   • write test OK
   • event storage OK
   • communication attachments OK

7. Open Admin → Communications and test with your own/internal address first:
   • choose a communication purpose
   • select one child
   • attach a small test poster
   • send
   • confirm the email arrives with the poster
   • confirm the communication history shows the attachment

NEW COMMUNICATION WORKFLOW
--------------------------
• Choose Project updates, Event invitation/poster, Harper's Heroes recognition, or Essential family/service communication.
• Tick individual children, several children, or choose Select all eligible.
• Consent is enforced for updates, events and recognition.
• Essential/service communication requires a separate confirmation and must not be used to bypass promotional/event consent.
• If siblings share one family email address, one private email is sent but the communication is logged against each selected child.
• PNG, JPEG, WebP and PDF attachments are supported up to 10 MB.
• Attachments are stored in a private Supabase bucket and delivered to Resend through a short-lived signed URL.
